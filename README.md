# Анализ хайпа событий в IT

Командный проект по курсу «Наука о данных» Никифоров.
Исследуем, как меняется количество публикаций на Хабре вокруг событий:
когда возникает пик и как быстро затухает публикационная активность.

## Структура репозитория

- [`parser/`](parser/) — отдельный Python-парсер. Собирает статьи по поисковым
  запросам и сохраняет JSON: ID, ссылку, дату публикации, заголовок, пре-рид,
  теги и другие доступные поля. Инструкция запуска — в [README парсера](parser/README.md).
- [`metrics/`](metrics/) — Python-анализ собранной выборки `dataset.csv`.
  Скрипт `lab.py` отбирает статьи по событиям, убирает повторения внутри события
  и формирует дневные/недельные ряды, разрезы по тегам и ключевым словам.
  Рассчитанные CSV находятся в [`metrics/result/`](metrics/result/).
- [`metrics_draft/`](metrics_draft/) — исследовательский прототип расчёта пика,
  фона и полураспада (`metrix.py`), отдельные исходные JSON в `data/`
  и сводный отчёт `report.xlsx`. Методика прототипа требует согласования
  с итоговыми определениями метрик.
- [`processor/`](processor/) — Java 25 / Spring Boot / Spring Batch.
  Читает JSON из [`processor/data/`](processor/data/) через `MultiResourceItemReader`
  с делегатом `JsonItemReader`, преобразует статьи в `ArticleDocument`
  и сохраняет пачками в Elasticsearch через repository.
  `docker-compose.yaml` поднимает PostgreSQL для служебных таблиц Batch,
  Elasticsearch и Kibana.

## Обработка и визуализация

```text
Python-парсер → JSON → Spring Batch → Elasticsearch → Kibana
```

Парсер запускается отдельно. Процессор работает с подготовленными JSON;
обработка начинается по запросу `POST /api/jobs` с телом `{"jobName":"articleJob"}`,
а не при старте приложения. Статьи сохраняются в индекс `habr-articles`.
Kibana используется для просмотра публикаций и построения графиков.

## Метрики исследования

1. Количество уникальных статей по дням/неделям, по релевантным тегам
   и ключевым словам в период вокруг события.
2. Дата публикации каждой статьи — ось X временного ряда.
3. Время до пика — количество дней от события до максимума публикаций.
4. Высота пика — отношение дневного максимума к фоновому уровню до события.
5. Затухание — время возврата к фону либо период полураспада активности.

Для визуализации используем один индекс статей: основной ряд — в Kibana Lens,
производные показатели рассчитываются через агрегации Elasticsearch и Vega.
